# BDD: AI 引用偏好分析前端页面

## Feature: AI 引用偏好分析工作台

作为 GEO 内容运营人员，
我希望在前端页面中查看 AI 对来源、媒体、文章结构和信任锚点的偏好，
并能基于这些偏好直接创建优化文章和复测任务，
以便把“AI 喜欢什么内容”转化为可执行的内容生产动作。

## Background

假如系统已经接入 AI 回答来源抽取能力
并且系统已经有 `GET /visibility/source-preferences` 接口
并且系统已经有 `GET /visibility/source-preferences/prompts/{prompt_id}` 接口
并且系统已经有文章生成和内容优化任务接口
并且用户已登录并拥有当前租户或品牌的数据权限

---

## Scenario: 进入 AI 引用偏好分析页面

当用户从左侧导航进入“AI 引用偏好”
那么系统应展示 AI 引用偏好分析页面
并且页面应默认加载最近 90 天的数据
并且页面应展示筛选区、核心指标、来源偏好、文章结构、信任锚点和 Prompt 详情入口

验收标准：
- 页面路由建议为 `/visibility-monitoring/source-preferences`
- 左侧导航位于“可见度监测系统”下
- 页面初次加载应调用 `GET /visibility/source-preferences?days=90`
- 加载中展示骨架屏或 loading 状态
- 加载失败展示错误提示和重试按钮
- 无数据时展示空状态，并提示先执行模型可见度监测

---

## Scenario: 使用筛选区刷新偏好分析

当用户选择品牌、域名、时间范围、模型、Prompt 或关键词
并点击刷新
那么系统应按筛选条件重新请求引用偏好数据
并且页面中所有指标和图表应同步更新

验收标准：
- 时间范围至少支持最近 7 天、30 天、90 天、180 天、365 天
- 品牌和域名可以手动输入，也可以从已有数据中选择
- 模型筛选为空时表示全部模型
- Prompt 筛选为空时表示全部 Prompt
- 刷新时按钮显示 loading
- 刷新完成后保留当前 Tab
- 筛选条件应体现在接口 query 参数中

---

## Scenario: 查看顶部核心指标

假如接口返回引用偏好数据
当页面渲染完成
那么系统应展示核心指标卡
并且指标应帮助用户快速判断数据质量和优化机会

验收标准：
- 指标至少包含 AI 回答数、显式来源回答数、无显式来源占比、来源总数、已画像文章数
- 指标至少包含品牌提及率、推荐率、首推率、前三率
- 如果某项指标为空，应显示 `--` 而不是 0
- 无显式来源占比过高时应出现风险提示
- 已画像文章数为 0 时应提示“暂无可分析文章画像”

---

## Scenario: 查看来源偏好 Tab

当用户打开“来源偏好”Tab
那么系统应展示 Top 来源域名表格
并且系统应展示来源类型分布
并且系统应展示每个来源的引用次数、引用模型数和引用问题数

验收标准：
- 表格列至少包含来源域名、来源类型、引用次数、引用模型数、引用问题数
- 来源类型应使用标签展示，例如官网、知乎、公众号、百科、新闻站、行业站、普通网站、弱来源
- Top 来源域名默认按引用次数倒序
- 点击来源行可展开查看引用问题和模型
- 弱来源没有 URL 时仍应展示来源标题
- 无来源数据时展示空状态

---

## Scenario: 查看文章结构 Tab

当用户打开“文章结构”Tab
那么系统应展示 AI 更常引用的文章类型
并且系统应展示推荐文章结构
并且系统应展示高频结构特征

验收标准：
- 文章类型至少包含榜单推荐型、对比测评型、案例型、问答百科型、新闻报道型、官网说明型、通用文章型
- 页面应展示文章类型分布图或列表
- 页面应展示推荐文章结构文本
- 高频结构特征至少包含平均标题数、平均列表数、FAQ 出现情况、表格出现情况、平均正文长度、结构评分
- 如果文章画像数量不足，应提示“结构偏好仅供参考”

---

## Scenario: 查看信任锚点 Tab

当用户打开“信任锚点”Tab
那么系统应展示信任锚点命中率矩阵
并且系统应展示每个锚点的命中次数、命中率和建议动作

验收标准：
- 信任锚点包含客户原话、时间节点、使用场景、事实数据、身份信息、执行步骤、选择对比、权威引用、真实案例、持续输出
- 命中率高于等于 50% 时显示为优势项
- 命中率低于 35% 时显示为缺口项
- 缺口项应展示建议动作
- 事实数据缺口应提示补充可验证数据、时间节点和统计口径
- 权威引用缺口应提示补充行业报告、官方标准或专家观点
- 真实案例和客户原话缺口应提示不能编造客户名称或评价

---

## Scenario: 查看 Prompt 详情

假如用户从 Prompt 列表、来源行或操作按钮进入 Prompt 详情
当系统打开 Prompt 详情抽屉或详情页
那么系统应请求该 Prompt 的引用偏好数据
并且展示该 Prompt 下的来源、结构、信任锚点和核心指标

验收标准：
- 请求接口为 `GET /visibility/source-preferences/prompts/{prompt_id}`
- 详情展示 Prompt 文本、关键词、意图、场景
- 详情展示品牌提及率、推荐率、首推率、前三率、竞品提及率
- 详情展示 Top 来源、文章类型分布和缺失信任锚点
- 详情展示建议生成的文章类型和推荐结构
- 详情内应提供“生成优化文章”按钮

---

## Scenario: 从引用偏好创建优化文章

假如用户已经查看某个品牌或 Prompt 的引用偏好
当用户点击“生成优化文章”
那么系统应进入文章生成流程
并且自动带入当前引用偏好画像
并且用户应能确认或编辑文章生成参数

验收标准：
- 应带入品牌、域名、关键词、Prompt 文本和推荐文章结构
- 应带入 `source_preference_profile`
- 应默认开启 `use_source_preference`
- 用户可以关闭“使用 AI 引用偏好”
- 用户可以编辑文章渠道、生成模型、语言、风格和图片
- 提交后调用现有文章生成接口
- 生成任务详情中应能看到本次偏好快照

---

## Scenario: 查看生成后的信任锚点自检

假如用户基于引用偏好生成了文章
当文章生成完成
那么页面应展示生成结果的信任锚点自检
并且提示命中项、缺失项和风险项

验收标准：
- 自检结果来自 `trust_anchor_check_json`
- 展示命中锚点数量
- 展示未命中但本次要求命中的锚点
- 展示文章是否包含 FAQ、步骤、对比、数据、案例、引用
- 如果存在疑似编造或强承诺风险，应提示人工确认
- 自检结果不阻止用户保存或导出草稿

---

## Scenario: 创建内容优化复测任务

假如文章已经生成
并且用户准备发布或已经发布
当用户点击“创建复测任务”
那么系统应打开复测任务表单
并且要求用户选择发布前监测结果和填写发布 URL

验收标准：
- 表单至少包含文章、发布 URL、目标 Prompt、目标关键词、发布前 run
- 发布 URL 可以暂时为空，但为空时应提示无法判断直接引用
- 如果没有发布前 run，应提示先执行基线监测
- 提交后调用 `POST /content/optimization-campaigns`
- 创建成功后展示任务状态和下一步“发布后复测”按钮

---

## Scenario: 发起发布后复测

假如已经创建内容优化任务
当用户点击“发布后复测”
那么系统应调用复测接口
并且展示复测进度
并且复测完成后进入复盘报告

验收标准：
- 请求接口为 `POST /content/optimization-campaigns/{campaign_id}/retest`
- 默认沿用发布前 Prompt、模型和竞品配置
- 如果用户修改复测配置，应在页面提示“配置已变化，结果不可完全等比”
- 复测中应展示运行状态
- 复测失败应展示失败原因和重试按钮
- 复测成功后展示复盘报告入口

---

## Scenario: 查看复盘报告

假如内容优化任务已有发布前和发布后监测结果
当用户打开复盘报告
那么系统应展示发布前后指标对比
并且展示新文章是否被 AI 直接引用
并且展示归因结论和下一步建议

验收标准：
- 请求接口为 `GET /content/optimization-campaigns/{campaign_id}/report`
- 指标至少包含品牌提及率、推荐率、首推率、前三率、竞品提及率、显式来源占比
- 展示每个指标的发布前值、发布后值和变化值
- 直接引用时展示引用问题、模型、引用片段和来源 URL
- 域名间接引用时展示域名引用来源
- 归因结论包含直接引用提升、域名间接引用、间接指标提升、暂无明显效果
- 报告必须展示“指标变化不等于绝对因果证明”的提示

---

## Scenario: 查看多轮复测趋势

假如同一优化任务已经执行多次复测
当用户打开趋势视图
那么系统应展示多轮复测指标变化
并且展示直接引用次数和域名引用次数变化

验收标准：
- 请求接口为 `GET /content/optimization-campaigns/{campaign_id}/trend`
- 趋势展示复测时间、品牌提及率、推荐率、首推率、前三率、直接引用次数、域名引用次数
- 能看到每次复测的归因结果
- 趋势数据为空时展示“暂无多轮复测”
- 趋势只展示当前租户有权限的数据

---

## 非功能验收

- 页面不得展示密钥、Cookie、私有配置或数据库内部字段
- 页面所有数据必须来自当前用户有权限的租户数据
- 接口失败、部分字段为空、画像不足时页面应降级展示
- 主要操作按钮应有 loading、成功、失败反馈
- 图表和表格在移动端不应发生文本重叠
- 生成文章和复测任务的关键操作应二次确认
- 页面文案应强调“引用偏好是辅助策略，不代表绝对因果”
