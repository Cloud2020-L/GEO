# BDD: AI 引用偏好统计、内容生成反哺与复测归因

## Feature: 基于 AI 引用偏好的内容优化闭环

作为 GEO 内容运营人员，
我希望系统能把 AI 回答中沉淀的引用来源和文章画像转化为可执行的内容策略，
并在文章发布后复测优化效果，
以便判断内容是否真的提升了品牌在 AI 回答中的可见性、推荐率和引用概率。

## Background

假如系统已经完成 AI 回答采集
并且系统已经从 AI 回答中抽取引用来源
并且系统已经对可访问来源文章生成内容画像
并且系统已经能计算品牌提及率、推荐率、首推率、前三率和竞品提及率
并且用户已选择一个品牌、官网域名、关键词或 Prompt 主题

---

## 阶段 3：AI 引用偏好统计

### Scenario: 查看品牌整体引用偏好

当用户打开“AI 引用偏好分析”页面
那么系统应展示当前品牌在指定时间范围内的引用来源统计
并且系统应展示 AI 最常引用的来源域名
并且系统应展示来源类型占比
并且系统应展示被引用文章类型分布
并且系统应展示信任锚点命中率
并且系统应展示无显式来源回答占比

验收标准：
- 可按品牌、时间范围、模型、关键词或 Prompt 过滤
- Top 来源域名至少展示域名、引用次数、引用模型数、引用问题数
- 来源类型至少包含官网、知乎、小红书、公众号、百科、新闻站、行业站、普通网站、弱来源
- 文章类型至少包含榜单推荐型、对比测评型、案例型、问答百科型、新闻报道型、官网说明型、通用文章型
- 信任锚点命中率覆盖客户原话、时间节点、使用场景、事实数据、身份信息、执行步骤、选择对比、权威引用、真实案例、持续输出
- 无显式来源回答应单独统计，不参与文章类型分布

### Scenario: 查看单个 Prompt 的引用偏好

假如某个 Prompt 已有多轮 AI 回答监测结果
当用户打开该 Prompt 的引用偏好详情
那么系统应展示该 Prompt 下最常被引用的来源
并且系统应展示该 Prompt 下高频文章结构
并且系统应展示该 Prompt 下信任锚点缺口
并且系统应展示品牌和竞品在该 Prompt 下的表现差异

验收标准：
- 能看到该 Prompt 的历史回答数量、成功回答数量和显式来源回答数量
- 能看到该 Prompt 下的 Top 来源域名和来源类型占比
- 能看到该 Prompt 下的高频文章类型和结构特征
- 能看到品牌提及率、推荐率、首推率、前三率、竞品提及率
- 能看到建议补齐的内容类型和信任锚点
- 能从该页面创建文章生成任务

### Scenario: 生成内容补齐建议

假如系统已积累来源文章画像
当用户查看引用偏好分析结果
那么系统应基于高频来源特征生成内容补齐建议
并且系统应区分“应该新增的文章类型”和“应该补充的信任锚点”

验收标准：
- 如果高频来源多为榜单推荐型文章，建议生成选择标准、榜单对比或服务商推荐类内容
- 如果高频来源多为问答百科型文章，建议生成概念解释、FAQ 或问题解决类内容
- 如果高频来源多为案例型文章，建议补充真实场景、客户反馈和落地过程
- 如果事实数据命中率低，建议补充可验证的数据、时间节点或统计口径
- 如果权威引用命中率低，建议补充行业报告、官方标准或专家观点
- 建议不得要求用户编造客户、奖项、数据或资质

## 阶段 4：引用偏好反哺文章生成

### Scenario: 创建带引用偏好的文章生成任务

假如用户从引用偏好分析页面创建文章任务
当系统进入文章生成流程
那么系统应自动带入品牌、关键词、Prompt 主题、推荐文章结构和信任锚点要求
并且系统应将引用偏好保存为本次生成任务的快照

验收标准：
- 生成任务应记录来源偏好快照
- 快照应包含 Top 来源类型、Top 文章类型、高频结构特征、高频信任锚点和缺口建议
- 快照保存后不应因后续统计变化而改变历史生成记录
- 用户可在生成前查看和编辑建议结构
- 用户可手动关闭引用偏好反哺

### Scenario: 生成写作简报

当系统生成文章写作简报
那么系统应把引用偏好转化为写作要求
并且系统应明确文章要覆盖的内容结构
并且系统应明确必须命中的信任锚点
并且系统应明确事实边界

验收标准：
- 写作简报包含文章目标、目标 Prompt、关键词、适用渠道和受众场景
- 写作简报包含推荐标题方向和正文结构
- 写作简报包含必须补充的信任锚点
- 写作简报只能使用品牌知识库、官网抓取内容、用户录入资料和已确认数据作为事实来源
- 写作简报不得包含参考文章原文段落
- 写作简报必须提示不得编造客户名称、合作案例、奖项、数据和资质

### Scenario: 生成符合 AI 引用偏好的文章

假如写作简报已经生成
当系统生成文章正文
那么文章应按照推荐结构组织内容
并且文章应尽量命中指定信任锚点
并且文章应保留品牌事实边界
并且文章应避免复用被引用文章的独特表达

验收标准：
- 正文应围绕当前 Prompt 的核心问题展开
- 正文应包含清晰小标题、可扫描段落和 FAQ 或总结模块
- 正文应体现使用场景、执行步骤、选择对比和事实数据中的至少若干项
- 如果缺少真实数据，文章应提示需要补充数据，不得自行编造
- 如果缺少真实案例，文章应使用泛化场景，不得伪造客户故事
- 生成结果应保存使用了哪些信任锚点

### Scenario: 生成后进行信任锚点自检

当文章生成完成
那么系统应对生成结果进行信任锚点自检
并且系统应展示命中和未命中的信任锚点
并且系统应给出可修改建议

验收标准：
- 自检结果展示信任锚点命中数量和命中明细
- 自检结果展示未命中的锚点和原因
- 自检结果展示正文是否包含 FAQ、步骤、对比、数据、案例、引用
- 自检失败不应阻止用户保存草稿
- 如果文章疑似编造事实，系统应标记风险并提示人工确认

## 阶段 5：发布后复测归因

### Scenario: 创建内容优化任务

假如用户准备发布一篇由系统生成的文章
当用户创建内容优化任务
那么系统应记录文章、发布 URL、目标 Prompt、目标关键词和发布前监测结果
并且系统应支持后续发起发布后复测

验收标准：
- 优化任务应关联品牌、域名、文章生成记录、发布 URL、目标 Prompt 和关键词
- 优化任务应记录发布前 model visibility run id
- 如果没有发布前监测结果，系统应提示先执行基线监测
- 发布 URL 可以为空，但为空时不能判断直接引用效果
- 同一篇文章可以关联多个 Prompt 或关键词

### Scenario: 发起发布后复测

假如文章已发布
并且优化任务已记录发布 URL
当用户点击“发布后复测”
那么系统应使用发布前相同的 Prompt 和模型重新提问
并且系统应保存发布后监测结果
并且系统应重新抽取 AI 回答引用来源

验收标准：
- 复测应默认沿用发布前的 Prompt、模型和竞品配置
- 用户可在复测前调整模型范围，但系统应记录配置差异
- 复测结果应保存为新的 model visibility run
- 复测过程中来源抽取失败不应影响指标计算
- 复测完成后应自动生成效果对比报告

### Scenario: 对比发布前后指标

假如发布前和发布后都有监测结果
当系统生成复盘报告
那么系统应对比发布前后的核心指标
并且系统应展示指标变化幅度
并且系统应判断优化效果类型

验收标准：
- 指标至少包含品牌提及率、推荐率、首推率、前三率、竞品提及率、显式来源占比
- 首推率按品牌排名等于 1 计算
- 前三率按品牌排名小于等于 3 计算
- 指标变化应展示绝对变化和相对变化
- 如果模型或 Prompt 配置发生变化，报告应提示不可完全等比
- 复盘报告应保留发布前和发布后的 run id

### Scenario: 判断新发布文章是否被 AI 引用

假如发布 URL 已填写
当系统分析发布后 AI 回答来源
那么系统应检查回答来源中是否出现发布 URL
并且系统应检查是否出现发布 URL 所属域名
并且系统应展示引用问题、模型、回答片段和来源 URL

验收标准：
- 精确匹配发布 URL 时判定为直接引用
- 匹配发布域名但不是发布 URL 时判定为域名间接引用
- 没有匹配 URL 或域名时判定为未引用
- 直接引用应展示问题、模型、引用片段、来源 URL 和回答时间
- 引用次数应按回答维度统计，不按 URL 重复出现次数统计

### Scenario: 输出复盘归因结论

当复盘报告生成完成
那么系统应给出优化归因结论
并且系统应给出下一步建议

验收标准：
- 如果新文章被直接引用，结论为“直接引用提升”
- 如果未直接引用但品牌提及率、推荐率、首推率或前三率提升，结论为“间接指标提升”
- 如果指标无明显提升且没有引用，结论为“暂无明显效果”
- 如果竞品提及率上升，报告应提示竞争压力增加
- 下一步建议应基于缺失信任锚点、低命中文章类型和未覆盖 Prompt 给出
- 复盘报告不得把相关性提升直接等同于因果结论

### Scenario: 多轮复测趋势

假如同一优化任务已经执行多次复测
当用户查看趋势
那么系统应展示多次复测的指标变化
并且系统应展示引用状态变化
并且系统应帮助用户判断内容是否逐步被 AI 采纳

验收标准：
- 趋势至少展示发布时间、复测时间、品牌提及率、推荐率、首推率、前三率和直接引用次数
- 能看到每次复测使用的模型和 Prompt 配置
- 能看到引用来源从无到有、从域名引用到 URL 引用的变化
- 能导出复盘结论
- 趋势只展示当前租户或当前品牌有权限的数据

## 非功能验收

- 所有统计和复盘数据必须按租户隔离
- 所有接口必须复用现有鉴权和租户过滤逻辑
- 不应在前端暴露数据库内部字段、密钥、Cookie 或私有配置
- 抓取失败、模型失败、部分来源缺失时，页面应展示降级结果而不是整体失败
- 文章生成必须保留事实边界，不能因为引用偏好而编造事实
- 复盘报告应提示“指标变化不等于绝对因果证明”

## 建议接口

- `GET /visibility/source-preferences`
- `GET /visibility/source-preferences/prompts/{prompt_id}`
- `POST /content/articles/generation-runs`
- `POST /content/optimization-campaigns`
- `POST /content/optimization-campaigns/{campaign_id}/retest`
- `GET /content/optimization-campaigns/{campaign_id}/report`
- `GET /content/optimization-campaigns/{campaign_id}/trend`

## 建议数据对象

- `source_preference_profile`：引用偏好统计结果
- `preference_snapshot_json`：文章生成时使用的偏好快照
- `content_optimization_campaigns`：内容优化任务
- `before_run_id`：发布前监测结果
- `after_run_id`：发布后复测结果
- `published_url`：文章发布地址
- `attribution_result`：直接引用、域名间接引用、间接指标提升、暂无明显效果
