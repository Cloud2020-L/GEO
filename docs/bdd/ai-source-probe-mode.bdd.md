# BDD: AI 来源采集模式与引用偏好闭环

## Feature: AI 来源采集模式

作为 GEO 内容运营人员，
我希望系统在不影响普通可见性监测指标的前提下，
能单独发起“来源采集模式”的模型提问，
让 AI 回答显式输出参考来源，
以便系统沉淀 AI 倾向引用的媒体、文章、结构和信任锚点，并反哺文章生成与复测评估。

## Background

假如系统已经有客户品牌、官网域名、Prompt 库、模型可见性监测和 AI 引用偏好分析页面
并且系统至少配置了一个可调用模型
并且用户已登录并拥有当前租户或品牌的数据权限
并且普通可见性监测仍用于统计品牌提及率、推荐率、首推率、前三率和域名引用率

---

## Scenario: 普通可见性监测不强制要求来源

当用户发起普通可见性监测
那么系统应继续使用普通用户视角提问
并且系统不应强制要求模型输出参考来源
并且系统应继续统计品牌提及率、推荐率、首推率、前三率、竞品提及率和域名引用率

验收标准：
- 普通监测的 Prompt 不新增“必须列出参考来源”的要求
- 普通监测结果仍写入原有模型回答和指标统计
- 普通监测中的回答如果自然包含来源，系统可以继续抽取
- 普通监测结果不应被来源采集模式污染
- 历史监测数据的统计口径不发生变化

---

## Scenario: 用户发起来源采集模式

假如用户已经选择品牌、域名、Prompt 问题和模型
当用户点击“采集 AI 来源偏好”或创建来源采集任务
那么系统应以来源采集模式调用模型
并且系统应在用户问题后追加来源输出要求
并且系统应记录本次任务类型为来源采集

验收标准：
- 任务类型应记录为 `source_probe`
- 来源采集模式应复用当前品牌、域名、Prompt 问题和模型配置
- 来源采集模式不应覆盖普通监测结果
- 用户可以从可见性监测结果页或 AI 引用偏好页面发起来源采集
- 任务执行失败时应保留失败原因和可重试入口

---

## Scenario: 来源采集模式的模型 Prompt 问法

当系统组装来源采集模式 Prompt
那么系统应保留原始用户问题
并且系统应追加明确的来源输出要求
并且系统应要求模型在回答末尾输出“参考来源”
并且系统应允许模型在没有明确来源时说明未找到明确公开来源

验收标准：
- Prompt 应包含品牌/项目名称
- Prompt 应包含官网域名
- Prompt 应包含原始用户问题
- Prompt 应要求自然回答，不要为了测试刻意堆关键词
- Prompt 应要求回答末尾增加“参考来源”部分
- Prompt 应要求尽量列出公开网页 URL、官网域名、媒体名称或文章标题
- 如果没有明确来源，模型应输出“参考来源：未找到明确公开来源”

推荐 Prompt 模板：

```text
请站在普通用户使用 AI 搜索的角度回答问题。

品牌/项目：{project_name}
官网域名：{domain}
用户问题：{question}

要求：
1. 自然回答，不要为了测试刻意堆关键词。
2. 如果你知道该品牌，请说明它能解决什么问题。
3. 请在回答末尾增加“参考来源”部分。
4. 参考来源请尽量列出公开网页 URL、官网域名、媒体名称或文章标题。
5. 如果没有明确来源，请写：参考来源：未找到明确公开来源。
```

---

## Scenario: 保存来源采集回答

当来源采集模式获得模型回答
那么系统应保存模型回答原文
并且系统应保存对应问题、模型、品牌、域名、任务类型和执行时间
并且系统应将该回答标记为来源采集回答

验收标准：
- 每条回答应关联来源采集任务
- 每条回答应保留原始 Prompt 问题
- 每条回答应保留模型 provider、model、vendor
- 每条回答应记录 `source_probe_enabled = true`
- 保存失败不应导致任务静默成功
- 回答为空或调用失败时应记录失败状态

---

## Scenario: 从来源采集回答中抽取来源

假如模型回答中包含 URL、域名、媒体名、文章标题或“参考来源”段落
当系统执行来源抽取
那么系统应抽取来源并保存到 AI 回答来源表
并且系统应标记来源类型和置信度
并且系统应将来源关联到原始回答和 Prompt 问题

验收标准：
- 明确 URL 保存为 `url_source`
- 明确域名保存为 `domain_source`
- 媒体名或平台名保存为 `media_source`
- 文章标题但无 URL 保存为 `title_source`
- 同一回答内重复 URL 应去重
- 来源应记录原始引用片段
- 来源抽取失败不应影响回答入库

---

## Scenario: 模型未输出明确来源

假如模型回答中没有 URL、域名、媒体名或文章标题
当系统执行来源抽取
那么系统不应报错
并且系统应将该回答标记为“无显式来源”
并且该回答仍应参与来源采集覆盖率统计

验收标准：
- 无显式来源回答不进入文章抓取队列
- 无显式来源回答应计入 `no_explicit_source_count`
- 页面应展示无显式来源占比
- 如果无显式来源占比过高，页面应提示需要优化来源采集 Prompt 或更换支持联网/引用的模型

---

## Scenario: 校验模型提及来源的真实性

假如系统已抽取到 AI 提及的来源
当系统执行来源校验
那么系统应验证 URL、域名或文章标题是否真实可用
并且系统应记录校验状态
并且系统不应把未校验来源直接视为真实引用

验收标准：
- URL 可访问时标记为 `verified`
- URL 不可访问时标记为 `unreachable`
- 只有域名时标记为 `domain_only`
- 只有文章标题时标记为 `title_only`
- 疑似模型编造来源时标记为 `suspected_hallucination`
- 校验状态应在来源偏好页面展示
- 未校验来源应归类为“模型显式提及来源”，不是“真实引用来源”

---

## Scenario: 抓取并画像已校验来源文章

假如来源 URL 已通过可访问校验
当系统执行来源文章画像
那么系统应抓取文章标题、正文、发布时间、媒体域名和正文结构
并且系统应分析文章类型、内容结构和信任锚点命中情况

验收标准：
- 文章画像应记录来源 URL、标题、域名、媒体类型和正文摘要
- 文章类型至少包含官网说明、新闻报道、行业文章、问答百科、对比测评、案例文章、榜单推荐和普通文章
- 内容结构应识别标题数、列表数、FAQ、步骤、表格、案例、数据和对比
- 信任锚点应包含客户原话、时间节点、使用场景、事实数据、身份信息、执行步骤、选择对比、权威引用、真实案例、持续输出
- 已画像 URL 不应重复抓取，除非用户手动刷新
- 抓取失败应记录失败原因

---

## Scenario: 统计 AI 来源偏好

假如系统已经积累来源采集回答、抽取来源和文章画像
当用户打开“AI 引用偏好分析”页面
那么系统应展示 AI 对来源、媒体、文章结构和信任锚点的偏好
并且系统应区分已校验来源和未校验来源

验收标准：
- 页面应展示 AI 回答数、显式来源回答数、无显式来源占比、来源总数、已画像文章数
- 页面应展示 Top 来源域名和 Top 媒体类型
- 页面应展示已校验来源数和疑似编造来源数
- 页面应展示高频文章类型和推荐文章结构
- 页面应展示信任锚点命中率和内容缺口建议
- 筛选条件应支持品牌、域名、模型、Prompt、时间范围和来源校验状态

---

## Scenario: 基于来源偏好生成优化文章

假如某个品牌或 Prompt 已有来源偏好画像
当用户点击“生成优化文章”
那么系统应把来源偏好画像带入文章生成
并且系统应要求生成文章补齐高频信任锚点
并且系统不得复制来源文章原文

验收标准：
- 文章生成请求应包含 `use_source_preference = true`
- 文章生成请求应包含 `source_preference_profile`
- 写作简报应包含推荐文章类型、推荐结构和必须补齐的信任锚点
- 生成内容应围绕原始 Prompt 问题展开
- 生成内容不得编造客户、案例、奖项、数据和资质
- 生成内容不得洗稿或复用来源文章独特表达
- 生成结果应输出信任锚点自检结果

---

## Scenario: 来源偏好文章发布后复测

假如用户已基于来源偏好生成文章并发布
当用户创建复测任务
那么系统应使用同一批 Prompt 和模型重新提问
并且系统应对比发布前后的可见性指标和来源指标
并且系统应生成复测归因报告

验收标准：
- 复测应对比品牌提及率、推荐率、首推率、前三率、竞品提及率和域名引用率
- 复测应检查新发布文章 URL 是否被模型提及
- 复测应检查来源类型和信任锚点分布是否变化
- 报告应展示优化前、优化后、变化值和可能原因
- 如果指标没有提升，报告应给出下一步内容补齐建议

---

## Scenario: 来源采集任务的数据权限

假如用户只能访问当前租户数据
当用户查看、刷新、导出或复测来源采集结果
那么系统只能返回当前租户授权范围内的数据
并且系统不应暴露其他客户的品牌、域名、Prompt、回答和来源

验收标准：
- 所有来源采集查询应按 tenant_id 过滤
- 来源文章画像应保留租户隔离关系
- 导出数据应脱敏敏感字段
- 错误日志不应输出密钥、Cookie、私有 URL 或客户敏感数据

---

## Scenario: 来源采集模式的质量门禁

当开发完成来源采集模式
那么系统应具备可自动验证的后端测试
并且前端页面应能展示来源采集结果
并且普通监测模式的原有测试不应回归

验收标准：
- 测试覆盖普通监测不强制来源
- 测试覆盖来源采集 Prompt 追加来源要求
- 测试覆盖 URL、域名、媒体名和文章标题抽取
- 测试覆盖无显式来源降级
- 测试覆盖来源校验状态
- 测试覆盖来源偏好统计
- 本地至少运行后端相关测试和前端类型检查
