# ZGEO 生产上线运行手册

## 访问入口

- 管理端：`https://admin.example.com`
- 客户端：`https://client.example.com`
- API：`https://api.example.com`

## 首次准备

1. 将 `deploy/production/.env.production.example` 复制为 `deploy/production/.env.production`。
2. 填入真实数据库密码、`JWT_SECRET`、模型 Key、媒介集市账号等生产变量。
3. 将 HTTPS 证书放入 `deploy/production/certs/live/<domain>/`，路径需匹配 `nginx.conf`。
4. 确认 DNS 已指向服务器。
5. 确认服务器已安装 Docker、Docker Compose、Node.js、npm。

## 发布流程

```bash
RELEASE_VERSION=20260509-001 scripts/deploy-production.sh
```

发布脚本会按顺序执行：

1. 发布前检查。
2. 本地 CI 和前后端构建。
3. 数据库备份。
4. 管理端/客户端静态产物按版本归档。
5. 后端镜像按版本构建。
6. Docker Compose 启动服务。
7. 检查 `https://api.example.com/health/ready`。

## 单独发布前检查

```bash
scripts/preflight-production.sh
```

检查内容：

- 生产 `.env.production` 是否存在。
- 是否仍有占位符。
- `JWT_SECRET` 是否足够强。
- 后端语法检查。
- 管理端和客户端是否能构建。
- Docker Compose 配置是否正确。
- 数据库连接和关键表检查。

## 手动备份数据库

```bash
scripts/backup-postgres.sh
```

备份文件会保存到：

```text
deploy/production/backups/postgres/
```

格式为 PostgreSQL custom dump，可用 `pg_restore` 恢复。

## 回滚

查看已有前端版本：

```bash
ls deploy/production/releases
```

回滚到指定版本：

```bash
scripts/rollback-production.sh 20260509-001
```

回滚会做两件事：

1. 将管理端和客户端静态文件恢复到指定版本。
2. 将后端服务切回同版本 Docker 镜像标签。

## 健康检查

```bash
curl -fsS https://api.example.com/health/ready
```

需要确认：

- `postgres` 正常。
- `qdrant` 正常。
- `task_queue` 正常。
- API 返回 HTTP 200。

## 常见发布参数

跳过发布前检查：

```bash
SKIP_PREFLIGHT=1 scripts/deploy-production.sh
```

跳过数据库备份：

```bash
SKIP_BACKUP=1 scripts/deploy-production.sh
```

跳过公网健康检查：

```bash
SKIP_REMOTE_HEALTH=1 scripts/deploy-production.sh
```

指定 API 健康检查地址：

```bash
API_HEALTH_URL=https://api.example.com/health/ready scripts/deploy-production.sh
```
