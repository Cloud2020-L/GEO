# Common Rules

- Treat this repository as the source of truth. Read the nearest code, tests, docs, and configuration before editing.
- Keep changes narrow, reviewable, and aligned with existing project structure.
- Preserve user work. If the worktree is dirty, avoid unrelated files and do not revert changes you did not make.
- Prefer existing helpers, patterns, commands, and conventions over new abstractions.
- Explain the final change in terms of behavior and verification, not only files touched.
- Do not modify global machine, editor, shell, Git, or Codex configuration for this project-level setup.
